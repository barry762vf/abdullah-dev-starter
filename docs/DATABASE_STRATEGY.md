# Database strategy

PostgreSQL 16 is used locally through `docker-compose.yml`; a compatible hosted PostgreSQL database can be used in production. `DATABASE_URL` uses `postgresql+asyncpg`. A dedicated `TEST_DATABASE_URL` ending in `_test` is required for integration tests, which refuse to run against the development database. See [README](../README.md).

Alembic revisions `001_initial_schema` and `002_pre_auth_hardening` create `users`, `roles`, `user_roles`, `refresh_tokens` and `audit_logs`. User and role IDs are UUIDs; timestamps are timezone-aware. Revision 002 enforces unique `lower(email)`, restricts deletion of assigned roles and records refresh-token revocation time. `refresh_tokens` stores only SHA-256 digests. `audit_logs` stores security and admin events without raw credentials. Actual models in `backend/app/models/` and migrations in `backend/alembic/versions/` define the schema.

Apply migrations once per release, through a direct or session-pooled connection: `python -m alembic upgrade head`. The migration environment serializes concurrent jobs with a PostgreSQL advisory lock. Then run `python -m app.core.seed` to insert missing baseline roles (`user`, `admin`, `superadmin`) without changing existing assignments. The first superadmin is created only by the explicit one-off `python -m app.core.seed --bootstrap-admin` command with temporary environment credentials; see [auth](AUTH_STRATEGY.md).

`/api/v1/health` reports process liveness without a DB query; `/api/v1/ready` checks database connectivity with a bounded timeout. Default per-process pool size and overflow are 5 and 5; tune them against database connection limits and worker count. `DATABASE_TRANSACTION_POOLER=true` disables asyncpg prepared-statement caches for transaction poolers. See [deployment](DEPLOYMENT_STRATEGY.md).
